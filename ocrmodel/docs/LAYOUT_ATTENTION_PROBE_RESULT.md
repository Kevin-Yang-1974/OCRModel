## 一、要回答的问题

模型自己的注意力里，有没有一个可读的「我现在读到哪一行」信号？

路由那轮（`bias2` 把 CER 从 0.1699 压到 0.1360）证明了「用真值字框给注意力加偏置」有效，但那一臂需要每步的真值字框，**不可部署**。可部署的版本得自己预测位置，而它只有在注意力本身带位置信号时才可能。本轮只观测、不干预，先把这个信号测出来。

失败模式不是「定位不准」，而是更根本的「**没有信号**」：若视觉总质量 $m_t$ 始终很低（模型主要靠语义 token 间注意力），定位从一开始就测不出来。这个判断要在阶段 1 早期做掉。

## 四、变换校验：重算的 logits 就是模型的 logits

这是本阶段唯一不可跳过的一项。探针自己重算 attention logits，它报的每个数都建立在「重算等于模型真实计算」之上——而**这是个测量，算错和算对长得一模一样**。

做法：用 `attn_implementation="eager"`（唯一会返回权重的路径）跑同一页的 prefill，把探针的 $m_t$ 与 $a^{\mathrm{vis}}$ 与模型自己的权重逐头、逐 query 位置比对。

**prefill 而非解码步**：探针的视觉 key 是在 prefill 捕获、之后每步复用的，所以变换必须正确的地方正是 prefill。

结果（bfloat16 权重 vs float32 重算）：

| 层 | $m_t$ 最大误差 | $m_t$ 平均误差 | $a^{\mathrm{vis}}$ 最大误差 | $a^{\mathrm{vis}}$ 平均误差 |
|---|---|---|---|---|
| 0 | 1.19e-2 | 6.9e-4 | 2.05e-2 | 2.8e-6 |
| 4 | 1.06e-2 | 1.0e-3 | 1.50e-2 | 3.0e-6 |
| 8 | 8.60e-3 | 1.1e-3 | 2.63e-2 | 2.8e-6 |
| 12 | 8.40e-3 | 8.3e-4 | 8.18e-3 | 3.4e-6 |

误差落在 bfloat16 的量化量级（相对精度约 0.4%，2496 个权重相加以致 $m_t$ 上约 1e-2），不是结构性差异——结构性错误（漏掉 RoPE、GQA 头映射错位、scale 缺失）会给出量级为 1 的差异。**校验通过**。复现：`tools/validate_attention_probe.py`。

### 4.1 两次失败记录（都是比对侧的错，不是变换的错）

第一次跑出 $m_t$ 误差 **1.0**，看起来像变换坏了，实际是**掩码被按行取错**：`_split_mask` 把掩码压平后只取第 0 行，这对解码步（q_len=1）正确，对 prefill 错误——因果掩码每个 query 位置一行，于是每个位置都拿「位置 0 的可见集合」去比。修正后保留行轴，返回可直接对 `[kv_heads, groups, q_len, keys]` 广播的形状。

**这条对真实运行没有影响**：解码步 q_len=1、本来就没有掩码（sdpa 对单 query 关掉 `is_causal`），全可见是对的。

校验器另有一个安全网：attention forward 经常以 `attention_mask=None` 调用、把因果交给 kernel，此时因果结构根本不存在于张量里。prefill 比对会因此把质量放到任何位置都看不到的 key 上，看起来就像变换坏了。校验器在这种情况下自行重建因果掩码，并记录 `mask_source`。

### 6.1 长度效应很大，裸 $m_t$ 不能直接判读

$m_t$ 是生成长度的函数：视觉 key 固定、文本 key 随生成增长，$m_t$ 单调下降。实测第 1 步平均 $m_t$ 0.374 vs 全步 0.221。记录里 $lse_{vis}$ 与 $lse_{text}$ **分开保存**就是为了这个——判读要用两者的差值或固定窗口，不能用裸 $m_t$。

### 6.2 「没有信号」这个失败模式没有被证实

$m_t$ 不接近零：15.1% 的头-行 $m_t>0.5$，第 8 层均值 0.408、logit 差 −0.49。方案 §4.2 的负面先验（来自写回诊断：decoder 不利用特征里的空间结构）**不排除**「模型自发注意力带空间定位」——这一轮的结果倾向于后者存在。

### 6.3 行读数本身是弥散的

`top_line_mass` 全体均值 0.201、背景质量均值 0.373，只有 11.6% 的头-行 `top_line_mass ≥ 0.5`。**单头的 argmax 是弱读数**，这正是方案里「先测各层各头的行概率、再估计行内位置」那条修订的理由：不能一上来就全头平均。相邻步保持同一 argmax 行占 66.6%（随机是 1/16≈6%），所以它远非随机，但每三步会跳一次。

### 8.2 已固定的置信度定义

按预登记纪律在 **select 页**上定，不在 check 页上改：

- **层/头**：第 8 层，头 `2,3,8,10,11,12,14,15`（依据 §8.1 的单头准确率表）。
- **聚合**：对固定 8 头的**行概率取均值**（不逐头择优）。理由：方案 §3 的修订明确要求先看行概率分布再估计位置，逐头择优是「按每步选最自信的头」，把置信度变成了选择器的输出；均值不需要每步第二次选择。
- **置信度**：均值读数的 `top_line_mass`，阈值 **0.5**。

select 页上该定义的覆盖 68.2%、准确率 100%；check 页覆盖 50.8%、准确率 100%。两者都过门槛（≥90% 准确率、≥50% 覆盖）。

## 九、本文件不下结论的地方

1. **4 页、945 个可评分字**。方案 §5 阶段 1 要求 24–32 页的开发子集。上表是链路自检加一个初步正向读数。
2. **真值行号是推断的**，来自编辑距离对齐后参考字符的框，不是直接真值。插入占 8%（48/591），歧义步 24 个，都已分开统计而不是摊进准确率。
3. **`noroute` 是 4 页基准**，与 149 页记录的 0.1699 不可直接比（页集不同）。这里的 0.1201 只用于两臂的逐位一致性判据。
4. 逐头择优是**按步选最自信的头**，其置信度是选择器的输出。它不使用真值，因此不是 oracle，但报告的是「选择器」的准确率，固定头的表现要另算。

置信度分箱在 check 页上是单调的（0.20–0.40 段 90.8% → 0.80–1.00 段 99.3%），这条是真的。

### 9.2.2 汇总量被单页支配，这是本节最重要的一点

| | select | check |
|---|---|---|
| 逐页准确率 中位数 | **0.962** | **0.965** |
| 逐页 最小 / 最大 | 0.171 / 0.994 | 0.879 / 0.991 |
| 逐页 极差 | **0.823** | 0.111 |

两个半边的**中位数几乎相同**（0.962 vs 0.965）。select 的均值低 8 个百分点，是因为
**其中一页塌了**：该页准确率 0.171，插入占 0.739——模型在那页大幅过生成，对齐把大部分
输出判成插入，定位随之崩掉。

所以「select 比 check 差 10 个点」不是半边之间的系统性差异，是**一页**。教训是：
**均值不是这个指标的可靠汇总量**，4 页那次读到的 97.1% 也因此偏乐观（28 页中位数 96.5%）。

### 9.2.3 对齐压力与两项测不了的东西

- **插入比例**：check 页逐页中位 9.6%、最大 34.7%。全局编辑距离对齐在过生成的页上要
  大量记插入，那页的「真值行号」本身就不牢靠。方案要求的「报告对齐覆盖率、插入与
  无法可靠定位的步单独统计」正是为了暴露这一点——它暴露了。
- **换行前后**：check 页 95.0%（2866 字）vs 行内 95.5%（969 字），**几乎相等**，没有出现
  4 页时「换行处更差」的模式。所以这一项至今**没有稳定结论**。
- **漏读/重复附近**：漏读邻域 92 字（占 2.4%）准确率 91.3%，干净邻域 95.2%——样本太小。
  **重复邻域在这 28 页上测不了**：按连续环的口径只找到 12 字（select）与 **0 字**（check），
  因为该子集只有 1 页触顶、基本没有病态复读。**0 字不能报成一个数**。

> 记录一次修错：复读标记最初沿用 `repeated_trigram_rate` 的口径（页内出现两次以上的
> 三元组），作为逐字标记它把一页的 **75%** 字标成重复——中文常见三元组本就大量复现，
> 那是在测量语言而不是故障。改成「周期 1–8 的子串连续重复至少三次」（即 `AdaptiveCycleLogitsProcessor`
> 处理的环）后，标记数从 2892 降到 12/0。

### 9.2.4 阶段 1 的判定

方案 §5 的规则是「仅行级可测则删除逐字跟踪目标；行级也不可测则停止」。按数据：

- **行级是可测的**：逐页中位数 96.5%，高置信准确率 99.4%，且大幅优于两个基准
  （均匀扫描 56.8%、保持上一行 25.2%）。
- **但预登记门槛未通过**，缺的是覆盖度（46.3% vs 50%），且覆盖度在 4 页时是 50.8%——
  它一直贴着门槛，样本一变就掉下去。

两条合起来的意思是：**读数可用，但「高置信覆盖过半」这个具体门槛没达到**。这属于方案
所说的「建议进入门槛……不是充分条件」，要不要据此进入阶段 2 是判断而非自动结论。
**不应该**因为逐头择优能过就改用它。

## 十、下一步

阶段 0 三项判据通过（§8.3），阶段 1 已跑（§9.2），**门槛在覆盖度一项上未通过**。

1. **决定是否进入阶段 2**：方案 §5 把它写成「建议进入门槛」，未通过不等于必须停止；
   但也不应改聚合方式让它通过。若进入，先做 `oracle_line`——**它决定整条路线生死**
   （字级→行级的收益能否保留完全未验证，而字级收益的主要来源可能正是被丢掉的精确定位）。
2. **覆盖度要么被解释、要么被修**：46.3% 贴着 50% 的门槛，而它衡量的是「读数有多自信」，
   不是「读数有多准」。可以考虑按页报覆盖（像 §9.2.2 那样）看它是否也被少数页支配，
   **但阈值和口径必须在这之前定死**。
3. **重复邻域需要在含复读的子集上测**：本 28 页里没有病态复读（0–12 字），这一项空白。
4. **敦煌的域迁移**：本文全部在 MTHv2（横向现代文档）上。古籍是竖排、异体字、无空格，
   而敦煌 manifest **没有字框通道**，阶段 1 的行定位真值在那里不存在。

**不要**据本文认为路线已通：注意力可观测 ≠ 行级偏置有收益，而阶段 1 的门槛本身未通过。
