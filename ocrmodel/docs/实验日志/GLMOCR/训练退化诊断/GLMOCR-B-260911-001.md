## 与上一轮结果下降的原因

### 1. 解码协议改变，旧低 CER 含有硬截断收益

上一轮 fast-screen / repeat-audit 的 A1 使用 `cycle_penalty=2.0` 和 `force_eos_steps=16`。检测到循环后如果 16 token 内不能脱离，就直接输出 EOS。旧 guard ON 的 CER 为 `0.394836/0.413352`，但删除数为 `3961/3802`；它主要通过截断循环降低插入，而不是让模型正确生成后续文本。

本轮关闭硬 EOS，要求模型脱离循环后继续生成到真实 EOS，因此原先被截断的插入和循环长尾会显现。新 A0/A1 与旧 guard ON 不是同一解码协议；旧的 `0.39–0.41` 不能直接当作新协议的公平基线。

### 2. checkpoint 起点不同

旧结果是 `glmocr_fast_screen_260910_r3_A1` 已训练 checkpoint 的 eval-only；A0/A1 是从基础权重重新训练 256 steps。旧 TF loss 为 `1.736313/1.698475`，新 A0/A1 约为 `1.81/1.78`，因此新 checkpoint 的识别状态本身较弱。

### 3. EOS 标签协议不同

旧标签没有显式 EOS（`eos_label_count=0`，目标 token 数 `23228`）；本轮每页补真实 EOS（`eos_label_count=64`，目标 token 数 `23292`）。这是学习正确停止所需的修正，但会改变监督分布和优化轨迹，不能直接比较两轮 loss。

### 4. A1 后半程出现附加目标的梯度竞争

A1 的第二次前向、scheduled sampling、continuation head 和 loop escape margin 在 step128 后逐渐生效。虽然 TF loss 从 `1.813698` 降到 `1.776209`，但 CER 从 `0.686485` 升到 `0.863078`，插入数和循环页率也上升，表明后程训练不稳定或附加损失权重过强。

### 5. 仍存在 exposure bias，且 dense page 长尾放大误差

teacher forcing 只在真实 OCR 前缀条件下计算局部 token CE；自由生成一旦前缀出错，后续 token 会在错误前缀上递归累积。关闭硬 EOS 后，密集页面的长序列更容易暴露该问题；旧 guard ON 密集页 CER 约 `0.6269`，新 A1 step256 约 `1.3318`。

## 结论

本轮下降由两部分共同造成：一是旧硬 EOS 截断造成的表观低 CER 不再存在，二是新 A0/A1 checkpoint 和 A1 后程优化确实较不稳定。当前最可信的筛选点是 A1 step128，但其 loop escape success 仍为 0，因此不能认定已经实现“停止循环后继续输出直到 EOS”。
