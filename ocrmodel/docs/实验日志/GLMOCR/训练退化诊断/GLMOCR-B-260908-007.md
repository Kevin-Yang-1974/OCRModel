## 结果判断

- 按三 seed 的 validation CER，attention 最佳点为 step64：`0.197089`，相对 content-only 绝对改善 `0.011322`。
- geometry 最佳点为 step192：`0.197106`，相对 content-only 绝对改善 `0.011305`；step256 仍仅改善 `0.000933`。
- layout_ot 最佳点为 step128：`0.202776`，绝对改善 `0.005635`；step256 反而恶化 `0.005877`。
- 因此 256 步末点没有显示出四组架构的稳定收益；收益主要出现在特定 checkpoint，且 exact-page rate 全部为 0。
- generation limit/EOS/长度只在约 3.1%–4.7%、95.3%–96.4%、368–376 tokens 范围内变化，不能解释全部 CER 跳变。

## 可比性审计

当前 architecture comparison 的 geometry/seed42 与 `GLMOCR-B-260908-006` 使用相同 protocol manifest hash、模型路径、Hungarian/full/FP32、LR horizon=128 和 validation-0 输出；但 step256 CER 分别为 `0.207115` 和 `0.190417`，训练指标与 checkpoint 输出不同。训练日志同时出现 CuBLAS、Flash Attention 和 Memory Efficient attention 的非确定性警告。说明当前 seed 不是严格可复现的单一轨迹，三 seed 均值可以作为探索性结果，但还不足以做确定性架构排名。

## 下一步

1. 先固定 CUDA/attention 可复现性（`CUBLAS_WORKSPACE_CONFIG`，并明确禁用非确定性 Flash/Memory-Efficient SDP 或统一 math SDP），再重跑 seed42 geometry 256 作为回归锚点。
2. 若回归锚点复现 `0.190417` 附近，再用同一确定性设置重跑四组；若仍不复现，继续追踪随机源与评估生成差异。
3. 在可复现性确认前，不把 attention step64 或 geometry step192 的单点收益登记为最终架构收益，也不读取 test。
