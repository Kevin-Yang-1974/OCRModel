# A0/A1 文本重复抑制与 teacher-forcing 曲线审计

## 目的

记录历史 fast-screen 中 A0（等预算控制）与 A1（文本重复抑制）的可比结果，核对 `training_ocr_loss` 与 validation teacher-forced loss 的统计口径，并判断 A1 的自由生成变化来自训练目标还是推理期循环守卫。本记录只使用 64 页分层 validation；800 页 test 未读取、未参与选点或阈值调整。

## 统一配置

| 项目 | 值 |
| --- | --- |
| 输入 | whole-page image + OCR prompt |
| mode / layout profile | `geometry` / `full` |
| query / assignment | 512 / `hungarian` |
| adapter / decoder | FP32 adapter；decoder LoRA rank 8、alpha 8 |
| train / validation | MTHv2 train 2159 页；固定分层 validation 64 页 |
| DDP | 5 进程；per-device batch 1；effective global batch 5 |
| steps / checkpoints | 256；validation at 128、256 |
| learning rate | adapter `5e-5`；decoder LoRA `1e-6`；warmup 32 |
| LR horizon | `lr_schedule_steps=128`；step 128 后进入最低学习率区间 |
| seed | 42 |
| validation manifest SHA-256 | `8fb3478d621f46c1d6f9dc7f5c400626af46dc068c6fc6b4ce2a519a3ccbba38` |

两组训练顺序、页面协议、模型、LoRA 和 layout loss 均相同。A0 未启用文本重复抑制；A1 启用 UL/EOS 配置（UL 权重 `0.1`、EOS 权重 `0.05`，最近 96 tokens，循环长度 8–32，连续 3 次），并在生成时使用 `cycle_penalty=2.0`、`force_eos_steps=16`。

A1 的循环页率和长度上限率下降，但删除错误约为 A0 的 2.6–3.2 倍，说明推理守卫压制循环的同时造成了过早终止。A1 的 CER 仍从 0.394836 恶化到 0.448864；因此不能把“循环率下降”直接解释为 OCR 主任务改善。

### 训练曲线口径核对

| 指标 | step 128 | step 256 | 口径 |
| --- | ---: | ---: | --- |
| 当前训练 batch `ocr_loss` | 1.295744 | 2.084871 | 当前 DDP optimizer batch 均值；不是全程均值 |
| 256-step `mean_ocr_loss` | — | 1.439102 | A0/A1 完全相同；全程记录均值 |
| validation teacher-forced OCR loss | 1.736313 | 1.698475 | 固定 64 页、真实 OCR 前缀 |

远端训练日志共有 17 个记录点（step 1、16、…、256）。`ocr_loss` 范围为 `0.753901–2.836554`，最大值出现在 step 176；前 128 步均值 `1.265525`、标准差 `0.444480`，后 128 步均值 `1.450155`、标准差 `0.662050`。这表明后半程 batch 波动增大，但单个 step 256 端点不能作为单调恶化证据。

A0 与 A1 的 `ocr_loss`、`total_loss`、`auxiliary_loss`、`gradient_norm` 逐字段一致；A1 的 `text_unlikelihood` 和 `text_eos` 在全部日志点均为 `0`。step 128 与 256 的 `total_loss` 均满足 `ocr_loss + 0.2 × auxiliary_loss`（浮点残差约 `3e-8`），所以该历史 A1 没有产生有效 UL/EOS 训练梯度，实际变化来自推理期守卫。

## Teacher forcing 证据与解释

当前主线训练路径是标准 teacher forcing：

1. `ocrmodel/src/layout_ocr/data.py` 的 `prepare_training_inputs` 用真实 page OCR 构造完整 chat template，只将 prompt 部分的 labels 设为 `-100`。
2. `ocrmodel/src/layout_ocr/train_screen.py` 的训练 forward 调用 `model(**inputs)`，反向传播使用模型返回的 CE loss。
3. validation teacher-forced forward 重用同一真实 OCR 前缀；自由生成直到后续 generation 调用才发生。

因此，teacher-forced loss 下降与自由生成 CER 恶化并不矛盾：前者测量真实前缀条件下的局部 token 预测，后者会累积自身早期错误，存在 exposure bias。A1 还额外使用了强制 EOS 逃生策略，删除率上升与该策略一致。另一个可见混淆是 `lr_schedule_steps=128`：step 128 后学习率已接近最低值，后程平台不能归因于 teacher forcing 本身。

## 结论与后续约束

- 本历史对照不支持直接把 teacher forcing 替换为纯自由回归。
- A1 的训练目标与 A0 实际相同，不能据此证明 UL/EOS 训练有效。
- 继续实验应先在同一 checkpoint 上关闭硬 EOS/降低 cycle penalty，区分推理守卫副作用；若仍有 free-run 退化，再只加入小比例 scheduled sampling，并把 `lr_schedule_steps` 改为 256。
- 训练日志应同时保留当前 batch、16-step EMA、全程 token-weighted OCR loss、teacher-forced validation loss、mixed-prefix loss 和 UL/EOS 激活比例；不再用单个 128/256 端点判断趋势。
