# line100 3–5 字窗口的 beta 强度扫描（B=1.0–3.0）

2026-09-22。状态：已完成。五档全量 149 页，一卡一档。

## 为什么扫这个

窗口臂的 `B=1.0` 是从**整行臂**继承来的，从来没有针对窗口扫过。剂量测量第一次把两者的差别量化了：

| 目标形态 | 每步命中 token |
| --- | ---: |
| 3–5 字窗口 | 7.39 |
| 整行（臂的 `regions` 框） | 69.27 |

同一个 `B=1.0` 在窗口上只有整行**十分之一**的每步加性总量；而整行在 `B=2.0` 就崩坏，那条悬崖是在每步偏置 69 个格子的剂量下测出来的。窗口只有 7.39 个格子，它的可用区间不可能与整行相同，`B=1.0` 是否已到峰、是否偏右，此前完全未知。

## 判读

### 1. 窗口的峰在 1.0 之上、1.5 与 2.0 之间，比整行低

`B=1.5` 是所扫五档里最好的：CER `0.131944`，比记录值低 `0.004994`。`B=2.0` 已经开始崩坏（CER `0.174341`、触顶 2 页），`B=2.5/3.0` 继续恶化。

**崩坏的量在插入，替换基本不动**：

| 相邻档 | 插入变化 | 替换变化 |
| --- | ---: | ---: |
| 1.0 → 1.5 | 948 → 826（−13%） | +31 |
| **1.5 → 2.0** | **826 → 2575（×3.1）** | +25 |
| 2.0 → 2.5 | 2575 → 1651 | −39 |
| 2.5 → 3.0 | 1651 → 3753（×2.3） | +551 |

这与整行在 `B=2.0` 崩坏的形态**同类**（插入从 1948 炸到 7972、5 页触顶），而触发的每 key 值恰好也是 `B=2.0`。两臂崩坏点相同、但每步覆盖差近十倍，**独立复现了 `LAYOUT_ORACLE_LINE_RESULT.md` §7.1 的结论：决定崩坏的是每 key 的强度，不是加性总量**。

反过来说，**窗口的可用上界（约 1.5）比整行（1.0–1.5，2.0 崩坏）并不更高**，尽管它的每步剂量小一个量级——所以「每 key 强度」这条量纲在两个臂上是一致的。

### 2. `B=1.5` 的优势不稳健，且集中在极少数页

`B=1.5` 对 `B=1.0` 的逐页配对 bootstrap：

| 口径 | ΔCER | 95% CI | 判定 |
| --- | ---: | --- | --- |
| 按页 | `−0.004994` | `[−0.010909, −0.000494]` | 显著（P=0.989） |
| **按卷号分组（33 卷）** | `−0.004994` | `[−0.005977, +0.003045]` | **不显著**（P=0.771） |

逐页计数：**B=1.5 更好 39 页、更差 35 页、打平 75 页**；总字符错误 `8921 → 8755`。改善高度集中——单页最大改善 `+90 / +36 / +25 / +17`，而退步页都很小（最大 `−15`）。

对照：`B=2.0` 对 `B=1.5` 按卷 CI `[−0.007035, +0.049487]` 也不显著；`B=3.0` 对 `B=1.5` 按卷 CI `[−0.660901, +0.006733]` 也不显著。**在这个装置上，按卷分组的 33 个卷让大部分逐档比较都落在不显著区**，所以本轮的**方向性**（1.5 最好、2.0 起崩坏）比任何单档的显著性更可信。

### 3. 工程含义

- 记录配置的 `B=1.0` **不是**窗口的最优值，但也不是明显错误：1.5 相对 1.0 的按页改善显著、按卷不显著，属「值得记下、不足以改记录配置」的量级。
- **`B≥2.0` 不可用**：插入错误翻倍到三倍、出现触顶页。
- 若要把最优值夹出来，还需补 `1.25 / 1.75` 两档；本轮已能确定峰在 `[1.0, 2.0)` 且**靠近 1.5**。
- 记录配置（`B=1.0`）的验收结论**不受影响**：它本来就 `passed=false`，本轮没有把它变成通过，也没有替它改参数。
