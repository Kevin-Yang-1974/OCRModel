# GLM-OCR decoder-mask 筛选实验监控交付任务

> 交付对象：任意可执行 shell 命令的助手（GPT）。全程只读，任务结束后中文汇总。

## 任务目标

只读监控一个正在远端 A100 上运行的 5 卡筛选实验，直到全部完成或任一失败，然后汇总关键指标回报。**全程只读**：不重跑、不重启、不杀 job、不改远端文件、不做任何 git 操作、不读 test 划分。

## 背景（为什么跑这个）

GLM-OCR 的 decoder-mask routing 机制筛选。上一轮 mask head 训练出「密集列级条」（Dice≈0.02，mask_mean 从 0.02 涨到 0.125，从不定位）。本轮在损失里加了 centroid（质心）+ sparsity（L1 质量）两项，并加 LR warmup + cosine 退火，看能否让 mask 定位。两个 oracle 测「完美 routing」能达到的 CER 上限，用于对照 B0 零样本基线 CER=0.287（同一 64 页 validation 集）。

## 远端信息

- 主机：`a100-yky`（SSH 免密，BatchMode；需本机 `~/.ssh/config` 已配置该别名）
- 访问方式：`ssh -o ConnectTimeout=15 -o BatchMode=yes a100-yky '<命令>'`
- 启动时间：2026-09-22 约 08:48（远端本地时间），预计全程 ~1 小时
- screen_id：`glmocr_decoder_mask_oracle_128step_v1`

## 路径

```text
R=/data3/yky/yangky_ocr_models/glm_ocr_layout_mask_routing
SR=$R/training_runs/glmocr_decoder_mask_oracle_128step_v1
```

五个 job（每卡一个，单进程、非 DDP）：

| 卡 | job | 产物目录 |
| --- | --- | --- |
| GPU0 | 训练臂 G1（window head，MLP 989K） | `$SR/arms/G1/` |
| GPU1 | 训练臂 G2（token head，MLP） | `$SR/arms/G2/` |
| GPU2 | 训练臂 G3（vae head，5.3M） | `$SR/arms/G3/` |
| GPU3 | oracle `line`（生成期注入整行 GT mask） | `$SR/oracle/line/` |
| GPU4 | oracle `window`（生成期注入 3-5 字 GT mask） | `$SR/oracle/window/` |

## 终态判定

- 训练臂「完成」：`$SR/arms/<臂>/train_log.jsonl` 与 `$SR/arms/<臂>/validation.json` **两个文件都存在**。
- oracle「完成」：`$SR/oracle/<mode>/summary.json` 存在。
- 任一 job「失败」：`$SR/arms/*/train.log` 或 `$SR/oracle/*/run.log` 中出现任一关键字：`Traceback` / `RuntimeError` / `out of memory` / `CUDA error` / `FileExistsError`。

## 监控节奏

立即检查一次当前状态，之后**每 30 分钟检查一次**。当「5/5 全部完成」或「任一 job 失败」时停止轮询并进入汇总。若到 ~2.5 小时仍未终态，回报当前部分状态和仍在运行的 job。

## 完成后要回报的内容（中文）

1. 每个训练臂 G1/G2/G3：
   - 完成还是失败；
   - 从 `train_log.jsonl` 最后一行读：`loss`、`bce`、`dice`、`centroid`、`sparsity`、`mask_mean`、`mask_max`、`mask_p95`；
   - 从 `validation.json` 读 step-128 的 CER；
   - 有无 NaN/Inf。
2. 每个 oracle line/window：从 `summary.json` 读 `metrics.CER`、`generation_limit_hit_rate`、`reads_ground_truth`。
3. 结论判断：
   - mask 是否定位了（mask_mean 应接近目标 ~0.005、centroid 应下降、不再列级条）；
   - oracle 上限 CER 是否低于 B0 基线 0.287。
