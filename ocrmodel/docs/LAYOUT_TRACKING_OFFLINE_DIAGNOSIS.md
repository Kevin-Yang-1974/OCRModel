## 一、探针重放：修正置信度有效，但「保持」与「单调」都是负结果

### 1.1 为什么能离线重放，以及凭什么相信它

跟踪臂的整条决策链（每步选哪一行、门控放不放行）**只是 probe 文件里每步每头行分布的纯函数**。
重放唯一额外需要的是「读这一步注意力时，偏置加在哪一行」，而这个可以从文件本身还原：路由钩子
读的是**上一步**探针写下的估计。所以第 $s$ 步被偏置的行 = 第 $s-1$ 步被接受的估计。

重放记录策略（`recorded@6`）必须复现路由报告自己的门控数，否则重建是错的：

| | 门控步数 |
|---|---|
| 路由报告 `track100.routing.jsonl` 汇总 | **4754** / 50407 |
| 重放 `recorded@6` 重建 | **4754** |

**逐位相同 ⇒ 重建（含一步滞后）正确。** 工具把这条写成了自动判据（`--routing-report`），
每次重放都打印比对结果，不靠一次性脚本。

### 1.2 修正本身是精确的

偏置对某一行的所有 key 加常量 $B$，等于把该行 softmax 权重整体乘 $e^B$（重归一化前）。
所以乘 $e^{-B}$ 再归一化**精确还原**无偏分布。probe 逐头存了分布，因此**逐头各自用各自的
归一化因子**修正，而不是近似地修正平均后的分布。被偏置的行取观测该步时 `tracked.line`
的值——上一步写下、且被路由带进本次前向的那个值。

跟随**路由自己的框判据**而不是 region owners：两者在框重叠时不一致（owner 是读序第一个包含
该 token 的框，偏置覆盖某个框内的全部 token），修正必须减掉**实际加上的**那份。

### 1.3 结果：按覆盖率读，不按门槛读

§9.1 的教训是门槛一改，**剂量跟着改**，所以表格按 `coverage` 排序（覆盖率 = 拿到偏置的字符占比）。
每格是「tracked 实际施加的那一行 == 该字符真值行」的准确率，与阶段 1 的定位口径同分母。

匹配覆盖率处（≈0.994）：

| 策略 | coverage | 施加行准确率 |
|---|---|---|
| **`corrected@0.5`** | 0.9941 | **0.8873** |
| `corrected_hold@2.5` | 0.9951 | 0.8841 |
| `corrected_hold@3` | 0.9939 | 0.8808 |
| `recorded@0.5`（现行为，无修正） | 0.9947 | 0.8765 |
| `hold@3` | 0.9939 | 0.8680 |
| `mono@0.5` | 0.9947 | 0.8332 |

三条读数：

1. **偏置校正的置信度值 +1.1 个点**（0.8873 对 0.8765，覆盖率还略高）。
   在覆盖率 0.991 处同样 +1.0 点（`corrected@1` 0.8856 对 `recorded@1` 0.8758）。
   §8 测到的缺陷确实可以被解析地扣掉。
2. **「门控拒绝时保持上一行」是负结果。** 固定门槛下 `hold` 看起来更好，但那**全是剂量**：
   在匹配覆盖率处它比丢弃**更差**（0.8680 对 0.8765）。§9.1 的 `mean_boxes_hit` 证据
   支持的是「门槛与剂量耦合」，不是「丢弃损失剂量」。
3. **「读序单调」是更强的负结果**（0.8332，比现行为低 4.3 个点）。读序是**可部署信息**
   （检测器成对准确率 MTHv2 0.937 / 敦煌 0.980），但行估计**合法地会往回走**——
   硬单调约束毁掉信息而不是去噪。

### 1.4 一个必须标注的构造性事实

置信度单位是 `top_line_mass × num_regions`，所以它**不可能超过页面的行数**：6× 的门槛在
少于 6 行的页面上不可达。MTHv2 sparse24 validation 的行数分布是 **min 8 / median 24 / max 24**，
所以这份数据上不构成损失；换数据集（敦煌短页）时必须重算这条。

## 二、漏行归因：检测器是「没看到整列」，不是「框放偏了」

### 2.1 §5.2 留下的问题

§5.2 实测漏掉的框中位高 796px、匹配上的 782px（**重采样后坐标**，train_line_detector 的
1200×2400 缩放，原图尺度约 ×1.25），排除了分辨率与「小框检测不到」，并明确写下下一步：
「需要看『未匹配的预测框是否落在某个未匹配的真值框内』来区分『没看到那一列』与『看到了但框放错了』」。
**这条到现在才做。**

### 2.2 结果（149 页 2993 框，导出阈值 0.2，IoU 0.5）

| 漏行成因 | 框数 | 占漏行 | 高 p50 (px) |
|---|---|---|---|
| `absorbed` 被另一个已匹配框覆盖 | 29 | 7.0% | 1049 |
| `box_off` 有自由框重叠但 IoU < 0.5 | 55 | 13.4% | 1014 |
| `coarse` 自由框覆盖过半但 IoU 低 | 0 | 0% | — |
| **`unseen` 没有任何框与它重叠** | **328** | **79.6%** | **1030** |

阈值 0.3 的旧导出同向：`unseen` 81.3%、`box_off` 10.6%、`absorbed` 8.1%。

**答案很干净：近八成的漏行没有任何预测框与它重叠**，而且它们是**整列**（中位高 1030px，与匹配上的一样长），
不是小目标。所以既不是分辨率、也不是回归精度，而是**这些列根本没进模型的输出**。

### 2.3 虚警框的镜像结论

431 个未匹配预测框：

| 虚警位置 | 框数 | 占比 | 与匹配行的 IoU 中位 |
|---|---|---|---|
| 落在**已匹配**的行上 | **326** | **75.6%** | 0.462 |
| 落在未匹配的真值行上 | 50 | 11.6% | 0.393 |
| 落在空白/栏间 | 55 | 12.8% | **0.002** |

**只有 12.8% 的虚警真的在背景上**；四分之三压在一条已经被匹配到的行上。

不过「重复」这个词要按重叠强度分档说，不能只用 0.1 的下限：

| 与匹配行的 IoU | 框数 | 占虚警 | 含义 |
|---|---|---|---|
| ≥ 0.5 | **123** | 28.5% | **真重复**，NMS 在 0.5 就能去掉 |
| [0.3, 0.5) | 97 | 22.5% | 同一列的偏移框 |
| [0.1, 0.3) | 106 | 24.6% | 与匹配行部分重叠的相邻框 |

所以「75.6% 是重复框」**过强**；准确说法是「75.6% 与某条已匹配行有 ≥0.1 的重叠，其中 28.5%
是 IoU ≥ 0.5 的真重复」。两者对跟踪臂都不是中性的：§10.2 的反转说的是**选一个框**的臂里
虚警是候选，而一个与真列 IoU 0.46 的偏移框恰恰是**很容易被选中的候选**，所以 0.1 这一档
也不能当成无害。

**一个可测的推论**：导出侧对预测框再做一次 IoU ≥ 0.5 的 NMS（torchvision 默认 0.6，会漏掉
[0.5, 0.6) 那一带），精度从 0.857 升到约 0.893、召回不变。这是**不改训练**的改动，
值得与「修正置信度」并列作为跟踪臂的一个变体。

### 2.4 这指向什么

`unseen` 占八成的下一个问题是：这些列是**分数低于导出下限**，还是**模型压根没给候选**。
§5.1 已经测到检测器分数是双峰的（0.05/0.10/0.20 三档召回精度完全相同 ⇒ 0.05–0.2 之间没有框），
所以若它们低于 0.05，就必须用一次低阈值、关 NMS 的导出才能看见。**这是下一步最便宜的判定**
（149 页推理约 12 秒），而且两种答案的修法完全不同：前者是免费的导出口径改动，
后者才是训练问题（§5.4 的短行缺口 / 敦煌 train split）。

## 三、统计口径：分组 bootstrap 与「最坏情况」

### 3.1 加了什么

`tools/analyze_cer_significance.py` 现在并列报两档配对 bootstrap：

- **按页重采样**（既有口径，历史结果都在这下面报）；
- **按卷号分组重采样**（方案 §6 明确要求补的那档）：以页面 id 里的 `V...P...` 为版本/文档组代理
  （`EXPERIMENT_REGISTER.md` 已把这条写成可执行代理协议），无卷号的页合并为一组。

**口径细节**：`P` 后面的编号不全是纯数字（`V001P000D` 与 `V001P000F` 是同一卷的两页），
只用 `\d+` 会把两页并成一组，所以模式是 `V\d+P[0-9A-Z]+`，有测试专门盯这个。

### 3.2 跨零要读成区间，不是读成「没有差异」

方案 §6 要求「跨零即收益未确认」，这条守住了；但此前**没有登记下界**。现在每次都打印
`worst case still supported by the data`（两档里更保守的那个下界），因为
`pred_t04` 的 CI [−0.0070, +0.0745] 的含义是「最坏差 0.7 个点」，不是「没有收益」。

### 3.3 一段被顺带纠正的说法

旧文档写过「149 页同书页强相关使 CI 很宽」。同书相关会让**按页**口径的方差**偏小**（不是偏大），
所以真实的分组区间应当**更宽**。这条历史解释待同步；本文件的结论不依赖它。
