# 阶段 2：oracle_line —— 行框偏置保住了字框偏置的收益

**日期**：2026-09-20
**前序**：`plans/LAYOUT_ATTENTION_TRACKING.md` §5 阶段 2、`docs/LAYOUT_ATTENTION_ROUTING_RESULT.md`（字框路由的记录值）
**状态**：已跑完。结论是**行框偏置有效，机制与字框一致**。这是方案里「决定整条路线生死」的一步，判定为**可以继续**。

---

## 一、要回答的问题

记录的字框路由（`bias2`）把 CER 从 0.169924 压到 0.135977，配对 CI 不含零，**收益全在删除数
减半（1082→680）与插入数减半（1948→942）**，替换数几乎不动（4048→4042）。

但那需要**逐字的真值框**，只有标注能提供，**不可部署**。可部署的形态只能给出「大约在第几行」。
问题因此是：**字级→行级的降级，会不会把收益的主要来源丢掉？**

方案 §5 把这一步定为路线生死：若行框无改善趋势，则「可部署（无真值字级定位）」的路线在
原则上走不通，应停止，而不是继续投入注意力跟踪。

## 二、设置

| 项 | 值 |
|---|---|
| checkpoint | `glmocr_mthv2_sparse24_q32_layout_boxeq820_3000_from_boxeq58_a100_260916_v1/seed42/checkpoint-3000` |
| 数据 | MTHv2 sparse24 **validation 全 149 页**（不读 test） |
| 分辨率 | `max_pixels=4000000`（与记录的 0.169924 / 0.135977 同分辨率） |
| 指针 | `synced` |
| 臂 | `noroute` / `char2`（字框 B=2）/ `line025`（行框 B=0.25）/ `line050`（行框 B=0.5） |
| 判据 | 每臂对 `noroute` 的逐页配对 bootstrap（10000 次），CI 不含零才算 |
| 入口 | `tools/training/run_glmocr_layout_oracle_line_eval_a100.sh` |

行框由「当前读到的字所在的区域」给出：字符→行的映射按几何解出（读序第一个包含该字中心的
区域），与 `layout_targets`、探针同一规则，所以「第几行」在三处含义一致。

## 三、结果

| 臂 | 框来源 | $B$ | CER | 替换 | 插入 | 删除 | 触顶 | token/步 |
|---|---|---|---|---|---|---|---|---|
| `noroute` | — | — | 0.169924 | 4048 | 1948 | 1082 | 1 | 0 |
| `char2` | 字框 | 2 | 0.135977 | 4042 | 942 | 680 | 0 | 3.9 |
| `line025` | 行框 | 0.25 | 0.144332 | 3985 | 1003 | 1024 | 0 | 77.5 |
| **`line050`** | 行框 | 0.5 | **0.135377** | 4016 | 990 | **633** | 0 | 77.6 |

配对 bootstrap（基准 `noroute`，正区间表示该臂更好）：

```
char2    ΔCER +0.033946  (+20.0%)  CI [+0.006410, +0.084076]  显著
line025  ΔCER +0.025592  (+15.1%)  CI [-0.000779, +0.075272]  不显著（CI 含零）
line050  ΔCER +0.034547  (+20.3%)  CI [+0.007425, +0.084093]  显著
```

### 3.1 两个对照臂精确复现了记录值

`noroute` 0.169924、`char2` 0.135977，**与记录逐位相同**。这条是前提：若装置复现不出已知效应，
行臂的零结果就不说明任何问题。启动器把这条写成了硬判据。

### 3.2 机制复现了，不只是数字好看

记录的增益签名是「删除减半、插入减半、替换不动」。行臂给出一模一样的签名：

| | 替换 | 插入 | 删除 |
|---|---|---|---|
| `noroute` → `char2` | 4048 → 4042（−0.1%） | 1948 → 942（**−52%**） | 1082 → 680（**−37%**） |
| `noroute` → `line050` | 4048 → 4016（−0.8%） | 1948 → 990（**−49%**） | 1082 → 633（**−41%**） |

**行级约束做的是同一件事**：减少「跳过」和「重复」，而认字本身（替换）不动。方案 §5 担心的
「字级精度是收益的主要来源」**没有得到支持**——把框放宽到整行，收益基本保留。

## 四、一个必须说清的剂量问题：行臂不是「小幅」干预

方案的 §4.3 说「行框覆盖更多 keys，字框 B=2 的有效范围不能直接迁移」，实测把这个差别量化了：

| 臂 | 平均命中 token/步 | 每步加性 logits 总量（$B \times$ tokens） |
|---|---|---|
| `char2` | 3.9 | 2 × 3.9 = **7.8** |
| `line025` | 77.5 | 0.25 × 77.5 = **19.4** |
| `line050` | 77.6 | 0.5 × 77.6 = **38.8** |

**若按每 key 的 $B$ 说，`line050` 只有 `char2` 的四分之一；按总量说，它是 5 倍。**
所以：

- 行臂**没有增益时不能归因于「剂量太小」**——总量反而更大。
- 反过来，`line050` 在总量约 39 的情况下**没有崩坏**，而字框臂 $B=4$（总量约 13）就崩到
  CER 2.59、114/149 页触顶。这说明**决定崩坏的不是加性总量，而是每 key 的强度**：
  单个 key 上的 $B$ 大到能压过一切时，注意力被锁在单个字的框里；把同样多（乃至更多）的质量
  摊到整行许多 key 上，约束的是「在哪一行」而没有把「哪一个字」压死。
- 这条是一个**跨实验的比较**，不是受控剂量扫描：两次实验的框大小、$B$、页集都不同。
  它可解释、与两个实验都相符，但不能当作已验证的结论。**行臂的最优 $B$ 没有被界定**——
  试的两个里大的那个更好，说明可能的更优值没被排除。

## 五、阶段 2 的判定

方案 §5 的判据是「先确认 `oracle_line` 的 CER、插入/删除有改善趋势且无触顶恶化」：

| 判据 | 结果 |
|---|---|
| CER 有改善趋势 | **是**（`line050` 显著 +20.3%，`line025` +15.1% 但 CI 含零） |
| 插入/删除有改善趋势 | **是**（插入 −49%，删除 −41%） |
| 无触顶恶化 | **是**（行臂触顶 0，`noroute` 是 1） |

**判定：可以继续。** 方案给的那条停止条件（行框无改善趋势 → 路线原则上走不通）**没有被触发**。

## 六、这次没有回答的

1. **行臂的最优 $B$ 未知**（§4）：只试了两个，更大的那个更好，更优值可能是 0.75/1.0，
   也可能在某个点突然崩坏。方案 §5 说「门控 B=4 压力实验暂缓——先证明低增益方案有用」，
   现在这个前提满足了，压力实验可以排。
2. **`line025` 不显著**：CI [−0.0008, +0.0753] 含零。149 页的 CI 很宽（同书页强相关），
   所以「不显著」在这里主要是**功效不足**，不是「无效」。按方案 §6 可用分组 bootstrap 收紧。
3. **行框仍是评测真值**，不是预测地图。阶段 3 的 `predmap_static` / `predmap_track` 才是
   可部署形态；本文件只说明**若地图够准，行级约束有收益**。
4. **门控未测**：本轮都是恒定 $B$，方案 §4.3 的置信度门控 $c_{t-1}$ 还没接。
5. **仅 MTHv2 横向现代文档**。敦煌的域迁移前置（字级/行级框真值）仍未做。
