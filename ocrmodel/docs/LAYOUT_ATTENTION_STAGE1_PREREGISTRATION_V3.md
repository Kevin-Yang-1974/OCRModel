## 一、为什么要第三次

第二次登记（2× 均匀）在 check 页上**通过了**，但**这个通过几乎没有意义**：覆盖 98.8% 意味着
「高置信子集」就是全集，置信度那一项没起作用，通过的实质是「整体准确率 ≥ 90%」（§9.4.2）。
2× 取自第一次失败之后的扫描，去混淆的理由成立，但**没有意识到那个位置同时把筛选性丢掉了**。

所以这次要改的不是「去混淆」（那已经解决），而是**门槛的位置**，并且**把「必须有筛选性」
写成判定的一部分**，以免再犯同一个错。

### 2.1 6× 的依据（如实登记：依据是回顾性的）

6× 是在**已经看过两批页**的情况下选的。把 `stage1_v2` 两半的分箱累加，各门槛的表现是：

| 门槛 | check 覆盖 / 准确率 | select 覆盖 / 准确率 |
|---|---|---|
| 2× | 98.8% / 94.5% | 99.5% / 87.2% |
| 4× | 92.1% / 95.1% | 94.0% / 88.7% |
| **6×** | **76.5% / 95.9%** | **80.9% / 92.0%** |
| 8× | 61.4% / 97.6% | 64.3% / 93.4% |

选 6× 的理由：**两半的准确率都过 90%**，同时**覆盖降到 76–81%**——即门槛真的在筛。
4× 覆盖仍偏高（92–94%），且 select 准确率 88.7% 未达标；8× 覆盖虽仍过 50% 但收缩更多，
没有额外好处。

**这次数值的依据是回顾性的，第三次页集是唯一的独立证据。** 若在第三批页上不成立，说明该门槛
不稳定，不得再调。

## 三、登记页集

- 来源：MTHv2 sparse24 **validation**（149 页），**不读 test**。
- 抽取规则与之前完全相同（按真值长度排序等距抽取 28 页），**排除前两批已用的 56 页**
  （`stage1_v1` 与 `stage1_v2` 的 `validation_subset_stage.jsonl`），保证与前两批都不重叠。
  由 `GLMOCR_PROBE_SUBSET_EXCLUDE`（`:` 分隔多个清单）按构造保证，并断言不重叠。
- select/check 各 14 页，按长度序交替。
- **局限（如实登记）**：validation 全 149 页已用于历史探索，排除法只保证与前两批不重叠，
  **不构成全新盲测**。第三次页集之后的 149−28×3=65 页仍可再用一次，但边际独立性是递减的。

## 四、成本判据：同一次运行内串行重测

阶段 0 的成本判据一直没被可靠验证：两臂并行在同一主机上跑会互相争抢 CPU（探针开销主要在
Python 侧），`stage1_v1` 测出 +14.2%、`stage1_v2` 测出 **−4.4%**，**噪声盖过信号**。

本次在同一运行内**两臂串行**（同一张卡，先后执行，不并行），使两次计时处于同一条件。
登记：**额外时延 ≤ 20%** 为达标；**若仍为负值，判为测量无效**，不得记为达标。

## 五、这次结果该怎么读（登记在先）

| 结果 | 解读 |
|---|---|
| 覆盖 ∈ [50%, 90%] 且准确率 ≥ 90%，且优于两基准 | 门槛在第三批页上成立。**这仍只说明「位置可读」**，不代表行级约束有用（`oracle_line` 未跑）。 |
| 覆盖 > 90% | **`inconclusive`**：门槛没有筛选性，通过与否不说明问题（第二次登记的教训）。 |
| 覆盖 < 50% | 门槛过高，读数在足够多的步上不够自信。停止按现方案推进。 |
| 准确率 < 90% | 读数定位能力不成立。按方案 §5「行级也不可测则停止」，停止。 |

**不做**：结果出来后不改本文件的门槛、不换页集、不改头、不换聚合方式。
若需再改，写第四次登记并在第四批页上评测。

## 六、同时登记的辅助报告（描述性，不用于判定）

1. 逐页准确率与覆盖度，以及覆盖度与行数的相关（检验去混淆是否仍成立）。
2. 置信度—准确率分箱（无量纲口径，边界随量纲走）。
3. 换行前后 / 行内、漏读邻域、复读邻域、干净邻域。**复读邻域在前两批都是 0–25 字**，
   若本批仍无病态复读，如实记为空白而非报数。
4. 对齐压力：插入占比、歧义步、逐页插入占比。
5. 两臂逐页 token 一致（硬判据）+ 串行计时。
